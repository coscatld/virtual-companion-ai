# GA 项目架构

GA 分为企业版和个人版。企业智能体调用部署方配置的模型 API，个人终端可接入本机 vLLM 或 Ollama。两版各自启动和存储数据，共用 Python 对话、语音、记忆压缩和 BM25 实现。

## 企业版

Spring Boot 是控制面。它负责注册与登录、JWT 鉴权、伴侣配置、简报调度和请求分发。MySQL 保存账户、伴侣配置、简报设置和最新简报。Java 可以启用 Redis 统一限制用户的模型请求频率。Python 智能体通过 Redis 持久化对话记忆。

```mermaid
flowchart LR
    UI["企业版 Vue 界面"]
    JAVA["Spring Boot 控制面<br/>注册登录 · 鉴权 · 伴侣配置 · 调度 · 请求分发"]
    AGENT["Python gRPC 智能体<br/>对话编排 · 语音 · 记忆"]
    SQL[("MySQL<br/>账户 · 伴侣 · 简报")]
    REDIS[("Redis<br/>请求配额 · 对话记忆")]
    MODEL["企业模型 API<br/>对话 · 摘要 · 可选语音"]

    UI -->|"HTTPS REST，账户与设置"| JAVA
    JAVA -->|"SSE，流式文字"| UI
    UI <-->|"WebSocket，录音与语音回复"| JAVA
    JAVA -->|"WebSocket，简报推送"| UI
    JAVA <-->|"gRPC，文字流与双向音频"| AGENT
    JAVA <-->|"业务数据"| SQL
    JAVA <-->|"可选，跨实例配额"| REDIS
    AGENT <-->|"按用户及伴侣隔离"| REDIS
    AGENT <-->|"兼容 Chat Completions 的 API"| MODEL
```

典型对话由 Java 验证身份并读取人设，再将用户 ID、伴侣 ID、人设和请求交给 Python。文字生成通过 SSE 返回浏览器。语音经浏览器 WebSocket 和后端双向 gRPC 传到 Python，识别后进入同一套对话和记忆流程。简报支持在线推送，用户重新打开对话页也能看到最新一份。

通过 `GA_ENTERPRISE_LLM_*` 指定企业对话 API。摘要默认复用该 API，也可配置独立的 `GA_ENTERPRISE_SUMMARY_*`。部署企业智能体时只需提供模型 API 的网络访问，Python 进程负责请求和结果编排。

Java 可以配置 `GA_ENTERPRISE_REDIS_URL` 开启跨实例配额控制。Python 的记忆连接单独由 `GA_REDIS_URL` 配置，两个连接可以指向同一 Redis。启用 `GA_INTERNAL_TOKEN` 时，Python 验证 Java gRPC 请求携带的服务令牌。Python 在非回环地址上提供 gRPC 服务时要求此配置。

## 个人版

个人版只有一个常驻后台，即 Python FastAPI。安装包同时包含浏览器界面和 `ga` 命令。令牌、伴侣配置及对话记忆存在本机数据目录中的 SQLite，模型通过独立 API 接入。Docker 镜像和 Python 安装包都启动同一个 FastAPI 应用。

```mermaid
flowchart LR
    DOCKER["Docker 镜像<br/>持久卷 /data"]
    WHEEL["PyPI 格式分发<br/>wheel / sdist"]
    BROWSER["桌面或手机浏览器<br/>内置个人终端"]
    API["单进程 FastAPI<br/>Bearer 鉴权 · 伴侣设置 · 文字与语音"]
    CORE["Python 对话核心<br/>语音 · 记忆 · BM25"]
    SQLITE[("本机 SQLite<br/>令牌 · 伴侣配置 · 三层记忆")]
    MODEL["推理服务<br/>本地 vLLM 或 Ollama · 独立 ASR 与 TTS"]

    DOCKER -->|"启动 ga"| API
    WHEEL -->|"安装后启动 ga"| API
    API -->|"提供静态页面"| BROWSER
    BROWSER <-->|"HTTP(S)，SSE、WAV 上传和语音回复"| API
    API --> CORE
    API <-->|"身份与设置"| SQLITE
    CORE <-->|"读取与写入记忆"| SQLITE
    CORE <-->|"对话、摘要和语音"| MODEL
```

安装后运行 `ga`。后台默认监听 `127.0.0.1:8081`，在浏览器访问该地址。在另一终端运行 `ga token` 获取访问令牌。个人界面可以调整名字、人设和声音标识，并在重新打开时读回近期对话。

| 交付方式 | 构建命令 | 运行方式 | 数据位置 |
| --- | --- | --- | --- |
| Docker | `docker build -t ga-personal:0.1.1 GAagent` | 容器执行 `ga`，映射宿主机端口 `8081` | 持久卷挂载到 `/data` |
| PyPI 格式 | 在 `GAagent` 执行 `python -m build` | 用 pip 安装 wheel 后运行 `ga` | `GA_DATA_DIR`，默认 Windows 的 `%LOCALAPPDATA%/GA` 或 Linux 的用户数据目录 |

个人版适合单用户或个人自托管。企业数据库和个人 SQLite 分别保存两版数据，当前没有跨版本同步。手机通过 HTTPS 访问时可使用浏览器麦克风。

## Python 代码结构

```mermaid
flowchart TD
    E["enterprise/<br/>企业 gRPC · Redis · 企业 API 配置"]
    P["personal/<br/>FastAPI · SQLite · 本地模型配置"]
    C["app/ 与 skills/memory/<br/>共享对话、语音、摘要与 BM25"]

    E --> C
    P --> C
```

企业版从源码使用 `python -m virtual_lover_agent.enterprise` 启动，安装 `requirements-enterprise.txt` 所列依赖。个人版使用 `ga` 或 `python -m virtual_lover_agent.personal`，安装包自带个人网页与共享核心。两个入口各自初始化传输与存储，再把模型配置和记忆实现交给共享代码。

## 个人版的本地模型

个人版通过 `GA_LLM_BASE_URL` 和 `GA_LLM_MODEL` 选择本地 vLLM 或 Ollama。对话和摘要可共用一个本地模型，也可分别配置到两个端点。Docker 镜像和 Python 安装包包含 GA 应用，模型权重由推理服务管理。[vLLM 快速启动](https://docs.vllm.ai/en/stable/getting_started/quickstart/) · [Ollama 兼容 API](https://docs.ollama.com/api/openai-compatibility)

## 共用的三层记忆

```mermaid
flowchart TD
    SEND["一轮文字或语音完整结束"] --> RAW["层一 · 近期原文<br/>上下文最多取 10 轮"]
    RAW -->|"超过 10 轮，压缩最早 3 轮"| SUM["摘要模型"]
    SUM -->|"确认写入后移除已摘要的原文"| ROLL["层二 · 滚动摘要<br/>最近 4 条"]
    ROLL -->|"更旧摘要"| ARCHIVE["层三 · 长期归档"]
    QUESTION["当前发言"] --> BM25["中英文 BM25"]
    ARCHIVE --> BM25
    BM25 -->|"最多 3 条相关记忆"| CONTEXT["组装模型上下文"]
    RAW --> CONTEXT
    ROLL --> CONTEXT
    QUESTION --> CONTEXT
```

Python 统一处理文字和语音的记忆写入。语音回合在生成可播放回复后保存。企业版使用 Redis，个人版使用 SQLite。两者共用上下文拼装和 BM25 评分，摘要异常时保留原始对话供下次重试。
